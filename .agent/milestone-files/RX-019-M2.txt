AUD-055: GlitchTip https DSN transport truth. The sink accepted https:// DSNs at parse time but delivery used a raw TcpStream and manually emitted HTTP - the scheme NEVER caused TLS negotiation, so a production https DSN silently sent the Sentry envelope (including incident body and DSN public key) over plaintext TCP. The transport is now scheme-authoritative: post_envelope checks dsn.is_https() BEFORE any byte is written; an https DSN MUST negotiate TLS through rustls 0.23 (ring provider, pinned to the locked workspace chain shared with infra/pki) with the standard webpki-roots store (custom RootCertStore supported via post_envelope_with_config for self-hosted private CAs); any TLS handshake/verify failure fails closed ExternalProvider with TLS detail and the envelope is NEVER sent in plaintext. An http DSN stays plaintext for local fixtures only. The HTTP write path is shared (write_and_read over plain TcpStream or StreamOwned<ClientConnection, TcpStream>); ServerName is derived from the DSN host with explicit-port stripping (IPv6 literals intact); Dsn gained scheme()/is_https() accessors. Hostile + positive regressions (5 new): https DSN against a REAL plaintext HTTP server fails closed ExternalProvider with TLS-layer evidence (never Accepted); https DSN delivers to a REAL rustls TLS server (self-signed cert in a custom root store, SAN localhost/127.0.0.1) and is Accepted - proving genuine TLS negotiation; host_without_port strips host:port but leaves IPv6 intact; empty-host https DSN rejected at parse; scheme accessors correct. nexus-glitchtip lib 44/44 (5 new aud055), clippy -D warnings clean, fmt clean; integration/stopped ep038 suites unchanged (http fixture).
