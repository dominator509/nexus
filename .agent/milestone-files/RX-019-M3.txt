AUD-056: incident correlation/trace context truth. Two defects hid correlation from the provider end to end. (1) Runtime redaction reconstructed telemetry with principal/tenant/request/correlation/trace/action context absent: ObservabilityRuntime::redact() always built a TelemetryContext with tenant/business_context/correlation/request_id/trace_id/span_id/source_interface all None, so an incident reported WITH a correlation reached the recording/GlitchTip sinks as an envelope whose context.correlation was None - the correlation existed only as a separate sink-port argument. (2) The GlitchTip sink explicitly ignored its correlation argument: report() named the parameter _correlation and never used it, and event_from_redacted only rendered envelope.fields into the Sentry event, dropping every safe context field (correlation, trace/span ids, request id, tenant, node, capability), breaking SPEC-007 behavior 3 ("GlitchTip ... receives release, environment, trace, and redacted user references"). Fixes: runtime.redact() now delegates to a new context-preserving redact_with_context(); report_incident builds the incident TelemetryContext WITH the caller correlation threaded into the envelope context and records/delivers that same envelope; a new report_incident_with_context accepts a caller-supplied validated context (tenant/correlation/request/trace/span/source_interface) and preserves it through redaction, so every downstream surface sees the same correlation. GlitchTip sink.report now consumes its correlation argument (threading it into the envelope context when the caller supplied one) and event_from_redacted renders the safe context metadata into the Sentry payload: correlation_id as tag+extra, trace_id/span_id tags, request_id extra, node extra, capability tag, and the tenant ONLY as a sha256 tenant_hash (never the raw TenantId), mirroring the OTLP tenant-hash convention. Hostile + positive regressions (6 new): runtime incident report preserves correlation in the quarantined redacted envelope context (was None); runtime redact_with_context preserves tenant/correlation/request/trace/span/source_interface; event mapping renders correlation/trace/request/node/capability and tenant hash while the raw tenant id never reaches the payload; no-correlation control omits correlation context; sink wire proof: a report WITH correlation delivered to a REAL local HTTP fixture carries the correlation id in the POST body; no-correlation control omits it. nexus-glitchtip lib 48/48 (4 new aud056), nexus-observability-ops lib 18/18 (2 new aud056), nexus-observability lib 27/27 unchanged, ep038 M3/M4 gate vacuity guards updated to real counts, clippy -D warnings clean, fmt clean.
