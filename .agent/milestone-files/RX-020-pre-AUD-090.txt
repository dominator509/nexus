## Finding

"The claimed final fresh-clone ship proof does not perform the ship-standard
fresh-clone run" (SPEC-008 behavior 4).

Affected: scripts/ep043-freshclone-accept.sh, SPEC-008 fresh-clone requirement.

## Root cause (two halves)

1. The acceptance only ran the EP-043 M1-M4 gates inside the clone, then
   REQUIRED a knowingly NOT_READY readiness report (`grep -q "NOT_READY"`)
   and wrote a markdown-only evidence file. It NEVER ran scripts/verify.sh,
   the production-readiness command (scripts/production-readiness-check.sh),
   or the full live-fire registry - so the "final fresh-clone ship proof"
   was structurally incapable of passing at true ship time and certified a
   NOT_READY tree as accepted.
2. Even if the ladder had been wired, the canonical fresh-clone evidence
   consumer (collectFreshCloneEvidence -> loadValidatedEvidence) requires a
   STRUCTURED ep043-freshclone-*.json ExecutionEvidence record (schema
   version 1, exit 0, VERIFIED, git_commit bound). The acceptance produced
   only markdown, so freshCloneRerun was ALWAYS false and no JSON producer
   existed anywhere in the repo.

## Reproducibility blocker discovered during the fix (same finding)

node-status-v2.sh validates each closure manifest's verify_log digest
against the file on disk. The *.log gitignore rule meant the 20 attested
closure verify.log files were never committed, so a fresh clone could never
reproduce node-DONE truth and graph-next.sh could never print ALL_DONE in
the clone - making the ship-standard fresh-clone run unreachable even at
true ship. Fixed: .gitignore negation + committed the 20 attested logs
(digests unchanged; closure manifests still validate).
